# Testing

## Levels

| Level | Harness command | Environment | Gate |
|---|---|---|---|
| integration | `uv run --with pytest==8.3.4 --with pyyaml==6.0.2 pytest -p no:cacheprovider tests/integration --tb=short` | local | build |
| smoke | `uv run --with pytest==8.3.4 --with pyyaml==6.0.2 pytest -p no:cacheprovider tests/smoke --tb=short` | production | deploy |

## Harness

- **Lifecycle.** Nothing is started: `local` tests read the repository's committed files, and production is always served by Vercel. Every level runs from the repository root.
- **Environment switch.** The level fixes the environment: `tests/integration` runs on `local`, `tests/smoke` on `production`. No variable is read.
- **Database access.** Not applicable: the site has no database.
- **Tools on the runner.** `uv` and `git` on PATH; `uv` provides Python 3.12 or later, pytest and PyYAML through the Levels commands. The smoke level needs network access to https://histand.net, https://ivan.histand.net and each host a case names. `tests/` sits at the repository root. No pack helper is available: area `site` has no `Target:` line and §1 of prd.md no `Pack:` line, so the area is on the default `service` pack, and the repository holds no `.prd-toolkit/` directory, so each test file holds its own helpers.
- **Clean state.** A test never writes inside the checkout, with one exception: the bytecode cache `__pycache__/` that Python writes beside each test file pytest imports, which `.gitignore` ignores (the owner, 2026-11-16: yes to "the 'tests never write in the checkout' rule excepts the git-ignored __pycache__/").
- **Persistent environments.** Production keeps its state: smoke tests only send GET and HEAD requests, and never deploy or change anything.
- **Layout.** `tests/<level>/test_<area>.py`, where the area is the feature file's name (`site`); each test's docstring cites its T-id, e.g. `@prd T-001.1`. Test roots: `tests/`
- **HTTP requests.** Python's `urllib.request` against the environment's Base URL, with a `User-Agent: prd-smoke` header; redirects are not followed, so a case asserts a redirect's status and `Location` header itself; no identity, since every page is public. A response header is looked up by its name in any letter case, and its value is compared exactly as sent, with no change of letter case or white space; a response body a case gives as text is decoded as UTF-8 and compared exactly. A case's `request` is one string, the method, a space and the URL; its `urls` are each sent with the case's `method`; `request` and `urls` are sent to the URL as written, its query string included. A response's `title` is the text of the first `title` element of its body, the body decoded as UTF-8 and parsed with `html.parser`, and is compared like other text (Assertions). `status` is the response's status code; `status-one-of` asks that it be one of the listed codes; `content-type` is the `Content-Type` header and `location` the `Location` header, each compared as sent, so a relative `Location` such as `/family` is not resolved against the request's URL; `body` is the body given as text; `body-equals-file` asks that the body's bytes equal the bytes of that file of the repository, a path from the repository root; a response's `json` is its body decoded as UTF-8, parsed with `json` and compared like a JSON file's `json` (Assertions). A case that sends several URLs gives its expected output keyed by each URL as written; or as `each`, whose keys every response must match; or as `each-status`, which asks that every listed URL answer that status.
- **Fixtures.** Not applicable: tests read the committed files; there is no test data to load.
- **Browser identity.** Not applicable: pages are checked as HTML text, not in a browser.
- **Assertions.** HTML is parsed with Python's `html.parser`, from a committed file read as UTF-8, the encoding each page declares (`<meta charset="utf-8">`, family.html:4, ivan.html:4); a case's `files` are paths from the repository root, and a case whose input is `checkout: the repository root` reads the checkout itself; only what a case lists is asserted.
  The parsed HTML is read as a tree of elements, text and comments in source order: an element named `area`, `base`, `br`, `col`, `embed`, `hr`, `img`, `input`, `link`, `meta`, `param`, `source`, `track` or `wbr`, and a self-closed tag, holds nothing; an end tag closes the nearest open element of its name and every element opened inside it; an end tag with no open element of its name is ignored; no end tag is implied, so a `p` or an `li` stays open until its own end tag; an attribute written with no value reads as the empty text, and an attribute written twice on one element keeps its last value; an element's text is the text of every text node under it, at any depth, joined in document order, and an HTML comment is not text; text and attribute values are compared exactly after HTML entities are decoded, each run of white space is collapsed to one space and the result is trimmed; the white space collapsed is HTML's ASCII white space only (space, tab, LF, FF, CR): a non-breaking space (U+00A0, `&nbsp;`) and other Unicode white space are compared as written; an element's class list is the value of its `class` attribute split at each run of white space, as Python's `str.split()` with no argument splits it; a `link` element's `rel` holds a word when that word is one of the space-separated tokens of its `rel` attribute, in any letter case; a key that ends in `-begins` asks that the text or attribute value start with the case's value.
  The head: `html-lang` is the `lang` attribute of the first `html` element; `meta-charset` is the `charset` attribute of the first `meta` element that has one; `title` is the text of the file's first `title` element; `link-canonical` is the `href` of the first `link` element whose `rel` holds `canonical`; each key of a case's `meta` is read from the first `meta` element in document order whose `name` or `property` attribute equals the key as written, searched in the whole file and not only in `head`, its value is that element's `content` attribute, and no count of such elements is asserted; `meta-theme-colors` is every `meta` element of the file whose `name` is `theme-color`, in document order, each as its `content` and `media` attributes, compared as one whole list, so their count is asserted.
  The body: `h1-texts` and `h2-texts` are the texts of every `h1` (or `h2`) element of the file, at any depth, in document order, compared as one whole list, so their count is asserted; `lede` is the text of the first `p` element whose class list holds `lede`; a case's `list-after-h2` names an `h2` by its text: the list is the first `ul` element whose start tag comes after, in document order, the first `h2` element whose text is the case's `h2`, and its items are the `li` elements that are children of that `ul`, in order, compared as one whole list to the case's `items`, so their count is asserted; an item's `link` is the first `a` element inside the `li`, at any depth, read as its text and its `href`; its `icon` is the `src` of the first `img` element inside the `li`, and `icon: none` asks that the `li` hold no `img` element; an item with no `icon` key asserts nothing of images; `desc-not-empty: true` asks that the `li` hold a `span` element whose class list holds `desc` and whose text is not empty; `every-icon` asks that every `img` element inside the list, at any depth, have each attribute it names with that value; a case's `paragraph-after-h2` takes the first `p` element whose start tag comes after the first `h2` whose text is the case's `h2`, and its `links` are every `a` element inside that `p`, at any depth, each as its text and its `href`, compared as one whole list in order; `contact-links` are every `a` element inside the first `p` element whose class list holds `contact`, at any depth, each as its text and its `href`, compared as one whole list in order. A page's visible text is the text of its `body` element, read like other text; `body-text-holds` asks that it hold each listed value, as written, anywhere in it; `body-text-words-none-of` asks that it hold none of the listed values as a word of its own, that is, letter case kept, at a place where neither the character before it nor the character after it is a letter or a digit (the start and end of the text count as neither), so `Postgres` is not found in `PostgreSQL`.
  Icons, references and scripts: `icon-links` is every `link` element of the file whose `rel` holds `icon`, `apple-touch-icon` or `manifest`, in document order, compared as one whole list, so their count is asserted; an item's `rel` is compared to the element's whole `rel` attribute value, each other attribute the item names (`href`, `sizes`, `type`) to that attribute, `href-begins` asks that the `href` start with the value, and an attribute the item does not name is not asserted; `loaded-references-local: true` asks that the `src` of every `img` element and the `href` of every `link` element whose `rel` holds `icon`, `apple-touch-icon`, `manifest` or `stylesheet`, each trimmed, either be `/` alone, or start with `/` with a second character that is not `/`, or start with `data:`, a file with no such element passing (a bare `/` counts as local: the owner, 2026-11-16), and an `img` element with no `src` attribute, or such a `link` element with no `href`, counting as not local (`tests/integration/test_site.py:302-305`, `tests/integration/test_site.py:316-320`; the owner's standing answer of 2026-11-16, "for a question about how tests compare or run, take the reading under which the current suite passes"); `script-elements` is every `script` element of the file, at any depth, in document order, each as its `type` and its `src` attribute, `src: none` meaning the element has no `src` attribute, compared as one whole list, so their count is asserted.
  Styles: a file's style text is the text of its first `style` element, read like other text (each run of ASCII white space collapsed to one space, the result trimmed), except that no HTML entity in it is decoded: the content of a `style` element is taken as the file holds it, as `html.parser` passes it (`tests/integration/test_site.py:52-59`, `tests/integration/test_site.py:141-142`, `tests/integration/test_site.py:330-333`; the owner's standing answer of 2026-11-16 on how tests compare), and neither page's `style` element holds a `&` (`family.html:59-223`, `ivan.html:78-242`; the owner's standing answer of 2026-11-16, "where a dry-run question is settled by a fact in the committed pages, take that fact"); a CSS comment (`/* … */`) is part of that text and is not removed; `style-holds` asks that the style text hold each listed value, as written, anywhere in it; `style-holds-none-of` asks that the text of every `style` element of the file, read the same way, hold none of the listed values.
  JSON: a JSON file (`vercel.json`, `site.webmanifest`) is read as UTF-8 (`tests/integration/test_site.py:190-191`), parsed with `json` and compared as data, and so are a response's `json` (HTTP requests) and a page's JSON-LD, which is the raw text of the file's first `script` element whose `type` is `application/ld+json`: its text exactly as the file holds it between the start and end tags, with no white space collapsed or trimmed (the owner, 2026-11-16: yes to "the structured data is parsed from its raw text"), parsed with `json`, and which a case gives as `json-ld`. Compared as data: in a mapping, each key the case lists is compared and a key it does not list is not asserted; a list is compared as one whole list, in order, so its length is asserted; a mapping that is an item of a list is compared whole, so the file's item holds exactly the case's keys and no other, and whole at every depth: a mapping or a list inside it is compared whole too (`tests/integration/test_site.py:169-181`, `tests/integration/test_site.py:184-194`, `tests/smoke/test_site.py:106-130`; the owner's standing answer of 2026-11-16 on how tests compare); strings, numbers and booleans compare exactly, with no white space collapsed. `json-redirects-include` asks that each listed item equal, whole, one item of the `redirects` array of `vercel.json`; `json-redirects-matching` asks that each listed item match one item of that array key by key, the keys it lists compared as data and an item's other keys not asserted (a list inside it, such as `has`, is still compared whole); and `json-redirects-count` is the number of items of that array. `json-ld-values-in-body-text` lists paths of keys into the page's JSON-LD, joined by `.` (`worksFor.name` is the `name` of the `worksFor` object); the value at each path is a string, and for `email` the string with a leading `mailto:` removed; each such string must be found, as written, in the text of the file's `body` element, read like other text.
  Other files: a case's `text` is the whole file decoded as UTF-8 and compared exactly, its line endings included; `text-holds` asks that the whole file, decoded as UTF-8 and read as written (no white space collapsed, letter case kept), hold each listed value anywhere in it, and `text-holds-none-of` that it hold none of them; `sitemap.xml` is parsed with Python's `xml.etree.ElementTree`, `xml-root` is the root element's tag in the `{namespace}name` form that library gives, and `xml-urls` is each `url` child of the root, in order, as the text of its `loc` and `lastmod` children in the same namespace, each trimmed, compared as one whole list; `files-exist` and `files-absent` ask that each path, from the repository root, be, or not be, a file of the checkout; `ignored` and `not-ignored` are paths each checked with `git check-ignore -q <path>` run from the repository root, exit 0 meaning ignored and exit 1 not ignored, a path that does not exist being checked all the same, and any other exit failing the test (`tests/integration/test_site.py:322-325`; the owner's standing answer of 2026-11-16, "for a question about how tests compare or run, take the reading under which the current suite passes").
  Known failures: a case with `known-failing:` is a strict expected failure, and its test fails, as not the known failure, on any result that is neither the expected output nor its `symptom:`, and fails as an unexpected pass when the expected output holds (`tests/integration/test_site.py:371`, `tests/smoke/test_site.py:188`; the standing answer above). Each symptom is seen as follows, and only then is the failure the known one: T-001.3's when README.md does not hold `family.html` and holds each of `Single-page`, `index.html` and `301` (`tests/integration/test_site.py:380-383`); T-002.3's when README.md holds neither `ivan.html` nor `https://ivan.histand.net/` (`tests/integration/test_site.py:406-407`); T-005.3's when the response's status is 200, whatever its `Location` (`tests/smoke/test_site.py:196-197`); T-010.2's when at least one listed URL answers a status other than 404 and every such answer is 200 (`tests/smoke/test_site.py:283-287`); T-010.3's when the repository root holds nothing named `.vercelignore` (`tests/integration/test_site.py:517-518`); T-017.3's when `knowsAbout` holds "Developer tools" and the list with every "Developer tools" item removed is exactly, in order, the five topics the case gives (`tests/integration/test_site.py:690-694`); T-017.4's when the visible text holds `Postgres` as a word of its own, whether or not it also holds `PostgreSQL` (`tests/integration/test_site.py:702-708`); each the owner's standing answer of 2026-11-16 on how tests compare.
  Errors: a case's `errors: []` asserts nothing: the site has no error codes (`contracts/errors.yaml:2` is `{}`), and no test reads the key (the tests of `tests/integration/test_site.py:338-793` and `tests/smoke/test_site.py:145-294` assert no error code; the same standing answer).
- **Waits.** A smoke request times out after 30 s; nothing else waits.
- **Effects.** Not applicable: no case runs anything that writes; each case's `effects` is empty, and `git check-ignore` writes nothing.
- **Leaks.** The site holds no classified data, so a leak check has nothing to scan; the Levels commands carry `--tb=short`, so a failure report prints no full tracebacks of test values.
- **Acceptance.** Not applicable: the PRD has no acceptance level.
- **Written rules and their citations.** Each reading rule in this Harness is written out in full, and the rule as written governs. A test line cited beside a rule records where that reading was taken from; it adds nothing to the rule and is not read in place of it. A test that disagrees with a written rule has misread the PRD (the owner, 2026-11-16, on the first site of this kind, prdanvil.com, and applied here by the owner's answer "all are confirmed" to item 8 of 2026-11-16).
